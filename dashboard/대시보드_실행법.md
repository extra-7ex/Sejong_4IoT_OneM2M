# 관제 대시보드 실행법

관제 대시보드는 tinyIoT MN-CSE에 쌓이는 레이더·위험 판단·Vision 데이터를 웹 화면으로 보여 줍니다.
CSE의 데이터를 읽기만 하고, 리소스를 만들거나 지우지 않습니다. 코드는 저장소 main 브랜치의 `dashboard/` 폴더에 있습니다.

- 저장소: https://github.com/extra-7ex/Sejong_4IoT_OneM2M
- 필요 조건: Python 3.8 이상 (표준 라이브러리만 사용, 추가 설치 없음)

---

## 1. Pi에서 켜기

Pi에 SSH 또는 VS Code Remote-SSH로 접속할 수 있는 경우입니다.

### 1-1. 코드 받기

처음 한 번:

```bash
cd ~
git clone https://github.com/extra-7ex/Sejong_4IoT_OneM2M.git
```

이미 받았다면 최신으로 갱신:

```bash
cd ~/Sejong_4IoT_OneM2M
git checkout main
git pull
```

### 1-2. Pi의 CSE 이름 확인

팀 기본값은 `TinyIoT-MN`이지만, Pi에 따라 예전 이름(`TinyIoT-mn`)일 수 있습니다. `200`이 나오는 쪽이 실제 이름입니다.

```bash
for C in TinyIoT-MN TinyIoT-mn; do
  echo "$C: $(curl -s -o /dev/null -w '%{http_code}' -H X-M2M-Origin:CAdmin -H X-M2M-RI:t1 -H X-M2M-RVI:3 http://127.0.0.1:3000/$C)"
done
```

### 1-3. 실행

`TinyIoT-MN`이 200이면 (팀 기본값):

```bash
cd ~/Sejong_4IoT_OneM2M
python3 -m dashboard.server --port 8080
```

`TinyIoT-mn`이 200이면 (예전 이름):

```bash
cd ~/Sejong_4IoT_OneM2M
DASH_CSE_BASE=http://127.0.0.1:3000/TinyIoT-mn \
DASH_RADAR_PATH=/forklift01/radar/la \
python3 -m dashboard.server --port 8080
```

아래 줄이 뜨면 켜진 것입니다.

```
대시보드: http://0.0.0.0:8080  (CSE http://127.0.0.1:3000/TinyIoT-MN)
```

- 터미널에는 이 한 줄만 나오고, 화면은 브라우저에서 봅니다 (2장).
- 이 터미널은 그대로 둡니다. 다른 명령은 새 터미널에서 실행합니다.
- 끌 때는 그 터미널에서 `Ctrl+C`를 누릅니다.

### 1-4. (선택) 터미널을 닫아도 계속 켜 두기

```bash
cd ~/Sejong_4IoT_OneM2M
nohup python3 -m dashboard.server --port 8080 > ~/dashboard.log 2>&1 &
```

- 예전 이름이면 앞에 1-3의 `DASH_CSE_BASE=…`, `DASH_RADAR_PATH=…`를 붙입니다.
- 끄기: `pkill -f dashboard.server`
- 로그 보기: `tail ~/dashboard.log`

## 2. 화면 보기

Pi에서 켜 둔 대시보드에 접속하는 방법입니다. Pi 주소는 Pi에서 `hostname -I`를 실행해 나온 첫 번째 값입니다.

| 상황 | 접속 주소 |
|---|---|
| Pi와 같은 Wi-Fi | `http://<Pi IP>:8080` |
| VS Code로 Pi에 접속 중 | 하단 **포트(PORTS)** 탭에서 `8080` 포트 전달 후 `http://localhost:8080` |
| Pi 화면(모니터)에서 직접 | `http://localhost:8080` |

- 휴대폰 브라우저로도 열립니다.
- 학교·도서관 Wi-Fi는 기기 간 통신을 막는 경우가 많습니다. 휴대폰 핫스팟에 Pi와 보는 기기를 같이 연결하면 확실합니다.
- Pi에 방화벽(ufw)을 켜 두었다면 한 번 열어 줍니다: `sudo ufw allow 8080`

## 3. 내 PC에서 켜기

Pi에 접속하지 않고, 내 PC에서 대시보드 서버를 돌려 Pi의 CSE를 읽는 방법입니다. PC가 Pi와 같은 Wi-Fi에 있어야 합니다.

1. 저장소를 받습니다 (`git clone` 또는 GitHub에서 **Code → Download ZIP**).
2. 브라우저에서 `http://<Pi IP>:3000/TinyIoT-MN`을 열어 응답이 오는지 확인합니다. 시간 초과가 나면 네트워크가 닿지 않는 것입니다.
3. 저장소 폴더에서 실행합니다.

Windows PowerShell:

```powershell
cd Sejong_4IoT_OneM2M
$env:DASH_CSE_BASE="http://<Pi IP>:3000/TinyIoT-MN"
python -m dashboard.server --port 8080
```

Mac·Linux:

```bash
cd Sejong_4IoT_OneM2M
DASH_CSE_BASE=http://<Pi IP>:3000/TinyIoT-MN python3 -m dashboard.server --port 8080
```

4. 그 PC 브라우저에서 `http://localhost:8080`을 엽니다.

Pi가 예전 이름이면 `TinyIoT-MN`을 `TinyIoT-mn`으로 바꾸고, `DASH_RADAR_PATH`를 `/forklift01/radar/la`로 지정합니다.

## 4. 장비 없이 화면만 확인

가짜 CSE가 사람이 지게차에 다가왔다 멀어지는 상황을 30초 주기로 만들어 줍니다. 발표 연습이나 화면 확인용입니다.

```bash
# 터미널 1
python3 -m dashboard.fake_cse --port 3900

# 터미널 2
DASH_CSE_BASE=http://127.0.0.1:3900/TinyIoT-MN python3 -m dashboard.server --port 8080
```

Windows에서는 터미널 2를 아래처럼 실행합니다.

```powershell
$env:DASH_CSE_BASE="http://127.0.0.1:3900/TinyIoT-MN"
python -m dashboard.server --port 8080
```

## 5. 화면 읽는 법

| 영역 | 내용 |
|---|---|
| 맨 위 | RiskEngine의 최신 판정(SAFE / WARNING / DANGER), 사유, 현재 거리, `t_cpa`, `d_cpa`. RiskEngine이 돌지 않으면 UNKNOWN |
| 왼쪽 지도 | 지게차를 위에서 본 그림. 아래 가운데가 지게차(레이더). 파란 점은 레이더 표적, 흰 동그라미는 Vision 추적, 빨간 점선은 위험 1.5 m, 노란 점선은 주의 3 m, 빨간 네모는 위험 이벤트가 자주 난 자리 |
| 데이터 수신 상태 | radar·events·fusedTracks·alert 각각의 수신 여부와 마지막 갱신 시각 |
| 이벤트 통계·기록 | 1시간 / 24시간 / 7일 동안의 상태 전환 횟수와 시간순 기록 |

- 레이더 점이 흐려지고 "끊김"이 뜨면 2초 넘게 새 레이더 데이터가 없다는 뜻입니다.
- "데이터 없음"은 해당 리소스나 데이터가 CSE에 아직 없다는 뜻입니다.
- 이벤트 기록은 대시보드를 켜 둔 동안 들어온 것만 남습니다 (`dashboard/data/events.jsonl`).

## 6. 자주 막히는 곳

| 증상 | 원인 | 조치 |
|---|---|---|
| 터미널에 아무것도 안 뜸 | 정상. 화면은 브라우저에 뜸 | 2장의 주소로 접속 |
| 브라우저에서 시간 초과 | 보는 기기와 Pi가 다른 네트워크 | 같은 Wi-Fi(핫스팟)에 연결하거나 VS Code 포트 전달 사용 |
| `{"m2m:dbg":"URI is invalid"}` | 대시보드가 아니라 tinyIoT(3000번)에 접속함 | 주소의 포트가 `8080`인지 확인 |
| MN-CSE가 빨간불 | 대시보드가 CSE에 닿지 않음 | `DASH_CSE_BASE`의 주소·이름 확인 (1-2) |
| 레이더가 "데이터 없음" | 레이더 경로가 다름 | 예전 이름이면 `DASH_RADAR_PATH=/forklift01/radar/la` |
| `Address already in use` | 8080을 이미 쓰는 중 | `pkill -f dashboard.server` 후 다시 실행, 또는 `--port 8081` |
| `No module named dashboard` | 실행 위치가 틀림 | `dashboard` 폴더가 보이는 저장소 폴더에서 실행 |
| `python`을 찾을 수 없음 (Windows) | 설치 때 PATH 미등록 | `py -m dashboard.server`로 실행하거나 재설치 시 "Add python.exe to PATH" 체크 |

## 7. 설정 (환경 변수)

| 변수 | 기본값 | 설명 |
|---|---|---|
| `DASH_CSE_BASE` | `http://127.0.0.1:3000/TinyIoT-MN` | 데이터를 읽을 CSE |
| `DASH_IN_BASE` | (비움) | 연결 상태만 표시할 IN-CSE. 예: `http://127.0.0.1:3001/TinyIoT` |
| `DASH_ORIGIN` | `CAdmin` | 조회 originator |
| `DASH_RADAR_PATH` | `/AE-forklift01/radar/la` | 레이더 최신값 경로 |
| `DASH_EVENTS_PATH` | `/AE-riskengine/events/la` | 위험 판단 이벤트 경로 |
| `DASH_FUSED_PATH` | `/AE-VisionAI/fusedTracks/la` | Vision 추적 경로 |
| `DASH_ALERT_PATH` | `/AE-forklift01/alert/la` | 경보 경로 |
| `DASH_POLL_S` | `0.5` | 조회 주기(초) |

자세한 동작 방식은 `dashboard/README.md`를 참고합니다.
