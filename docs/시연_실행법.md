# 시연 실행법 (Pi 한 대로 전체 파이프라인 켜기)

시연 방법은 두 가지다.

| | A. 시뮬레이션 시연 | B. 실제 레이더 시연 |
|---|---|---|
| 레이더 입력 | `radar/sim_rader.py` (가상 레이더) | `radar/radar_node.py` + LD2450 |
| 하드웨어 | Pi만 있으면 됨 | Pi + LD2450 (UART 연결) |
| 움직임 | 30초 시나리오 자동 반복 | 사람이 레이더 앞에서 직접 움직임 |
| 검증 상태 | Pi에서 전체 파이프라인 확인함 (2026-11-17) | 실제 LD2450으로는 아직 시험 안 함 (가짜 직렬 포트로만 확인) |

**둘 중 하나만 켠다.** 두 프로그램 모두 같은 `AE-forklift01/radar`에 쓰기 때문에, 동시에 켜면 값이 섞인다.

```
레이더(가상 또는 실제) → MN-CSE(3000) → RiskEngine → MN-CSE → 브리지 → IN-CSE(3001) → 대시보드(8080)
```

---

## 공통 준비 (시연 전 1번)

1. Pi와 시연 PC를 **같은 Wi-Fi**에 연결한다.
2. Pi IP를 확인한다. `hostname -I`를 실행하면 나오는 첫 번째 값이다 (예: `192.168.0.23`).
3. 시연 브랜치로 바꾸고 코드를 최신으로 받는다.
   ```bash
   cd ~/Sejong_4IoT_OneM2M
   git status --short
   git checkout feature/in-cse-bridge
   git pull origin feature/in-cse-bridge
   grep -c fresh dashboard/server.py
   ```
   - `git status --short`에 아무것도 안 나와야 한다. 파일이 나오면 Pi에서 누군가 작업 중인 것이다. 브랜치를 바꾸기 전에 그 사람에게 확인한다.
   - Pi는 여러 명이 같이 쓰기 때문에 다른 브랜치(예: `fix/least-privilege-acp`)로 바뀌어 있을 수 있다. 그래서 `git pull`만 하지 말고 브랜치를 꼭 지정한다.
   - 마지막 줄 결과가 0이 아니면 최신 코드다.
   - PR #24가 main에 머지된 뒤에는 `feature/in-cse-bridge` 대신 `main`을 쓴다.
4. CSE 2개를 켠다.
   ```bash
   sudo systemctl restart tinyiot-mn tinyiot-in-local
   systemctl is-active tinyiot-mn tinyiot-in-local
   ```
   `active`가 2줄 나오면 된다.

## A. 시뮬레이션 시연 (가상 레이더)

### A-1. 프로그램 4개 켜기

Pi 터미널에 아래 블록을 통째로 붙여 넣는다.

```bash
cd ~/Sejong_4IoT_OneM2M
pkill -f sim_rader; pkill -f radar_node; pkill -f engine.main; pkill -f mn_to_in_bridge; pkill -f dashboard.server
mkdir -p logs
nohup python3 radar/sim_rader.py > logs/radar.log 2>&1 &
ONEM2M_ORIGIN=CAdmin nohup python3 -m engine.main --transport polling > logs/engine.log 2>&1 &
nohup python3 -m onem2m.mn_to_in_bridge > logs/bridge.log 2>&1 &
DASH_IN_BASE=http://127.0.0.1:3001/TinyIoT nohup python3 -m dashboard.server --port 8080 --fresh > logs/dash.log 2>&1 &
sleep 5; pgrep -af "sim_rader|engine.main|mn_to_in_bridge|dashboard.server"
```

출력이 **4줄**이면 성공이다.

### A-2. 시연 중 보이는 것

가상 레이더는 30초짜리 시나리오를 계속 반복한다.

| 시간 | 레이더 | 대시보드 |
|---|---|---|
| 0~3초 | 사람 없음 | SAFE |
| 3~11초 | 5m에서 0.8m까지 접근 | 경고 → 위험 |
| 11~14초 | 0.8m에서 정지 | 위험 유지 |
| 14~20초 | 멀어짐 | SAFE로 복귀 |
| 20~30초 | 사람 없음 | SAFE |

## B. 실제 레이더 시연 (LD2450)

### B-1. 레이더 준비 (처음 한 번)

1. **배선**: LD2450을 Pi UART(`/dev/serial0`)에 연결한다.
   - 레이더 TX → Pi RX (GPIO15, 핀 10)
   - 레이더 RX → Pi TX (GPIO14, 핀 8)
   - 5V, GND
   - 추정: LD2450 신호선은 3.3V 레벨이라 Pi에 바로 연결할 수 있음. 연결 전에 모듈 데이터시트를 확인할 것.
2. **UART 켜기**:
   - `sudo raspi-config`를 실행한다.
   - Interface Options → Serial Port로 들어간다.
   - "login shell over serial"은 **No**, "serial port hardware"는 **Yes**로 설정한다.
   - 재부팅한다.
3. **패키지 설치**:
   ```bash
   sudo apt install python3-serial python3-paho-mqtt
   ```
4. **포트 확인**: `ls -l /dev/serial0` 명령으로 포트가 있는지 확인한다.

### B-2. 프로그램 4개 켜기

A-1과 비교해 **레이더 줄만 바뀐다** (`sim_rader.py` → `radar_node.py`).

```bash
cd ~/Sejong_4IoT_OneM2M
pkill -f sim_rader; pkill -f radar_node; pkill -f engine.main; pkill -f mn_to_in_bridge; pkill -f dashboard.server
mkdir -p logs
nohup python3 radar/radar_node.py > logs/radar.log 2>&1 &
ONEM2M_ORIGIN=CAdmin nohup python3 -m engine.main --transport polling > logs/engine.log 2>&1 &
nohup python3 -m onem2m.mn_to_in_bridge > logs/bridge.log 2>&1 &
DASH_IN_BASE=http://127.0.0.1:3001/TinyIoT nohup python3 -m dashboard.server --port 8080 --fresh > logs/dash.log 2>&1 &
sleep 5; pgrep -af "radar_node|engine.main|mn_to_in_bridge|dashboard.server"
```

출력이 **4줄**이면 성공이다. 레이더가 읽히는지는 다음 명령으로 확인한다.

```bash
tail -f logs/radar.log
```

레이더 앞에서 움직였을 때 업로드 로그가 올라가면 정상이다.

### B-3. 시연 방법

- 레이더 정면 약 5m 거리에서 레이더 쪽으로 천천히 걸어온다. 대시보드가 SAFE → 경고 → 위험으로 바뀐다.
- 뒤로 물러나면 SAFE로 돌아온다.
- 측정 단위는 mm다. 레이더는 최대 3명까지 동시에 표시한다.
- `radar_node.py`는 임시 판단으로 `alert`도 함께 기록한다(500mm 이내면 위험). 대시보드의 alert 표시는 이 값을 따른다.

## 화면 열기 (A·B 공통)

| 접속 위치 | 주소 |
|---|---|
| 같은 Wi-Fi의 다른 PC·휴대폰 | `http://<Pi IP>:8080` |
| VS Code로 Pi에 원격 접속한 PC | PORTS 탭에서 8080 추가 → `http://localhost:8080` |

`http://0.0.0.0:8080`은 서버 로그에 찍히는 값일 뿐, 브라우저에 넣는 주소가 아니다.

상태가 바뀔 때마다 하단 이력에 한 줄씩 쌓인다.

### 이력 초기화

이전 기록은 두 가지 방법으로 비울 수 있다.

1. **켤 때 자동으로 비워진다.** 대시보드는 기본적으로 켠 시각 이후의 이벤트만 이력·통계·핫스팟에 보여 준다.
2. **시연 도중에 비우려면** 이력 표 오른쪽 위의 **[화면 초기화]** 버튼을 누른다. 누른 시각부터 다시 쌓인다.

- 이전 기록은 지우지 않는다. IN-CSE의 `AE-safezone/events`에 그대로 남아 있고, 화면에서만 숨긴다.
- MN을 재시작할 때 밀려 들어오는 옛 레이더 데이터도 화면에 나오지 않는다.
- 이력 표 제목 옆에 `· 20:30:00 이후만`처럼 기준 시각이 표시된다. **이 표시가 없으면 옛 코드가 돌고 있는 것**이다. 공통 준비 3번부터 다시 한다.
- 이전 기록까지 모두 보려면 대시보드 줄의 `--fresh`를 `--all`로 바꿔서 켠다.

## 각 프로그램이 하는 일

| 프로그램 | 하는 일 |
|---|---|
| `sim_rader.py` / `radar_node.py` | 레이더 좌표를 MQTT로 MN의 `AE-forklift01/radar`에 올림 |
| `engine.main` | RiskEngine. 레이더 값으로 위험도를 판정해 MN의 `AE-riskengine/events`에 기록 |
| `mn_to_in_bridge` | MN 판정을 요약해 IN의 `AE-safezone/events`로 옮김 |
| `dashboard.server` | 관제 화면. 실시간 값은 MN에서, 이력은 IN에서 읽음 |

## 안 될 때

| 증상 | 할 일 |
|---|---|
| 화면이 안 열림 | 켜기 단계의 출력이 4줄인지 확인한다. Pi와 PC가 같은 Wi-Fi인지 확인한다. |
| 소스 상태가 빨간색 | `tail logs/engine.log logs/bridge.log`로 로그를 본다. 공통 준비 4번을 다시 한 뒤 켜기 블록을 다시 붙여 넣는다. |
| `radar_input_stale` / UNKNOWN | 레이더 입력이 끊긴 상태다. `tail logs/radar.log`를 확인한다. |
| (B) `radar_node` 실행 직후 종료 | `logs/radar.log`에서 오류를 확인한다. `/dev/serial0`이 없으면 B-1의 2번(UART 켜기)을 다시 한다. 권한 오류면 `sudo usermod -aG dialout $USER`를 실행하고 재로그인한다. |
| (B) 프로그램은 도는데 좌표가 안 올라옴 | 배선에서 TX/RX가 서로 엇갈리게 연결됐는지 확인한다. 전원도 확인한다. |
| 브리지 로그에 `timed out`이 한 번 찍힘 | 켜는 순간의 일시적인 지연이다. 계속 나오면 공통 준비 4번부터 다시 한다. |
| CSE가 갑자기 응답 없음 | 부하가 걸리면 tinyIoT가 가끔 죽는다. 공통 준비 4번을 다시 한다. |
| CSE 재시작 직후 `curl` 결과가 `000` | 밀린 메시지를 처리하느라 잠시 느린 것이다. `sleep 5` 후 다시 확인한다. |
| 다시 켤 때 `Address already in use` | 이전 대시보드가 남아 있는 것이다. `sudo fuser -k 8080/tcp` 후 다시 켠다. |
| `git pull`에서 `There is no tracking information` | Pi가 다른 브랜치에 있는 것이다. 공통 준비 3번처럼 브랜치를 지정해서 받는다. |
| `--fresh` 오류(`unrecognized arguments`) | 옛 코드가 실행 중이다. 공통 준비 3번을 다시 한다. |
| 켰는데 이전 기록이 그대로 보임 / `이후만` 표시와 [화면 초기화] 버튼이 없음 | 옛 대시보드가 아직 떠 있다. `sudo fuser -k 8080/tcp`로 끄고, 공통 준비 3번을 한 뒤 다시 켠다. 브라우저는 Ctrl+F5로 새로고침한다. |

정상 동작 확인:

```bash
tail -f logs/bridge.log
```

`IN 기록 #N`이 계속 올라가면 정상이다.

## 끄기

**레이더를 먼저 끄고, CSE는 그다음에 끈다.** MN이 먼저 죽으면 레이더가 보낸 MQTT 메시지가 쌓였다가, MN을 재시작할 때 한꺼번에 들어와 MN이 한동안 느려진다.

```bash
pkill -f sim_rader; pkill -f radar_node; pkill -f engine.main; pkill -f mn_to_in_bridge; pkill -f dashboard.server
```

다 꺼졌는지 확인한다. 아무것도 안 나오면 된다.

```bash
pgrep -af "sim_rader|radar_node|engine.main|mn_to_in_bridge|dashboard.server"
```

그래도 8080이 남아 있으면 `sudo fuser -k 8080/tcp`로 정리한다.

CSE까지 끄려면 다음 명령을 실행한다.

```bash
sudo systemctl stop tinyiot-mn tinyiot-in-local
```
